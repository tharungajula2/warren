### Core mechanism

| Monitoring lens | Typical evidence | What a breach asks |
| :--- | :--- | :--- |
| Outcomes | Realised versus predicted results | Has performance deteriorated? |
| Discrimination / calibration | Relevant performance instruments | Is ranking or level accuracy weakening? |
| Stability | Population and characteristic shifts | Has the model environment moved? |
| Data | Quality, missingness, lineage changes | Is the input process still fit? |
| Overrides / use | Frequency, direction and reason | Are users compensating for weakness or misusing output? |
| Limitations | Known constraints and assumptions | Has a known limitation become more material? |
| Operations | Failures, latency, dependencies | Is implementation or service reliability changing? |

```text
Signal
    ↓
Threshold breach
    ↓
Validate data / measurement
    ↓
Root-cause and materiality assessment
    ↓
Escalate
    ↓
Continue · Enhance controls · Restrict · Revalidate · Change · Retire
```

Thresholds can be hard limits, tolerance bands or qualitative triggers. They should be tied to the model's intended use and consequence, with escalation stronger when breaches are persistent, material or clustered across several indicators.

### Where it sits

```text
Upstream:   Approved use · Outcomes analysis · Stability · Production evidence
This:       Live monitoring and escalation
Downstream: Findings · Change · Restrictions · Retirement
```

### Ownership

| Role | Responsibility |
| :--- | :--- |
| Model owner | Runs or coordinates monitoring and investigates breaches |
| Business user | Reports use issues and decision impacts |
| MRM / validation | Challenges thresholds, trends and remediation |
| Governance body | Receives material or overdue escalations |

### Permanent rule

A threshold breach is a trigger for governed investigation, not an automatic diagnosis of model failure.

### Never confuse [Monitoring] and [Validation]

**Monitoring** - recurring first-line and governance surveillance of live performance, data, use and environment.

---

**Validation** - independent assessment of reliability and limitations, which can use monitoring evidence but is not replaced by it.

### Permanent trap

Resetting thresholds after repeated breaches merely to restore a green dashboard. Threshold changes themselves require rationale because they alter the institution's definition of acceptable model behaviour.

### Jurisdiction variants

No delta. The 2026 US guidance explicitly scales monitoring frequency and scope to model nature, new data, modelling approaches and materiality; that risk-based principle is consistent with sound MRM elsewhere.

<Recall
  q="Why is a dashboard without escalation rules incomplete?"
  a="It can show deterioration without determining who investigates, how materiality is assessed or what use restrictions follow, so information does not become control."
