### Core mechanism

This query does not return NULL balances:

```sql
SELECT account_id, outstanding_balance
FROM loan_snapshots
WHERE reporting_date = '2026-08-31'
  AND outstanding_balance &lt;&gt; 0;
```

Rows where `outstanding_balance` is NULL are neither equal to zero nor unequal to zero in ordinary two-valued logic. Test missingness explicitly:

```sql
SELECT account_id, outstanding_balance
FROM loan_snapshots
WHERE reporting_date = '2026-08-31'
  AND outstanding_balance IS NULL;
```

Aggregation has its own NULL behaviour. `COUNT(*)` counts rows, `COUNT(outstanding_balance)` skips NULL, and `SUM(outstanding_balance)` ignores NULL inputs but returns NULL if no non-NULL input exists for the group. Do not replace missing financial values with zero merely to make arithmetic convenient unless zero is genuinely the correct business meaning.

`COALESCE` is useful when a fallback is deliberate:

```sql
SELECT
    account_id,
    COALESCE(undrawn_amount, 0) AS undrawn_amount_for_output
FROM loan_snapshots
WHERE reporting_date = '2026-08-31';
```

NULL also matters in anti-filters. `NOT IN` can behave unexpectedly when the compared set contains NULL. A correlated `NOT EXISTS` is usually clearer for population exclusion because it asks directly whether a matching row exists.

```sql
SELECT a.account_id
FROM loan_accounts a
WHERE NOT EXISTS (
    SELECT 1
    FROM loan_snapshots s
    WHERE s.account_id = a.account_id
      AND s.reporting_date = '2026-08-31'
);
```

### Never confuse [NULL] and [Zero]

**NULL** - the value is absent or unknown.

---

**Zero** - the value is known and equals zero.

### Permanent rule

Test missingness with `IS NULL` or `IS NOT NULL`, and substitute a default only when the default preserves business meaning.

### Permanent trap

Writing `column = NULL` or `column &lt;&gt; NULL`. Those predicates do not identify missing rows; they evaluate to UNKNOWN.

### Jurisdiction variants

No delta. NULL logic is an implementation concept, not a regulatory one.

<Recall
  q="Why does `balance <> 0` not include NULL balances?"
  a="A comparison with NULL evaluates to UNKNOWN rather than TRUE, so the row does not pass the `WHERE` filter."
/>

<Recall
  q="What is the difference between `COUNT(*)` and `COUNT(balance)` when balance can be NULL?"
  a="`COUNT(*)` counts all rows, while `COUNT(balance)` counts only rows with a known non-NULL balance."
/>

<Recall
  q="When is `COALESCE(balance, 0)` safe?"
  a="Only when the business meaning of a missing balance is genuinely zero; otherwise the substitution destroys information about missingness."
