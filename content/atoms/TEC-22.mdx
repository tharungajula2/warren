### Core mechanism

Use `isna()` rather than equality comparisons to detect missing values:

```python
import pandas as pd

missing_balance = loans.loc[
    loans["outstanding_balance"].isna(),
    ["account_id", "reporting_date", "outstanding_balance"]
]
```

A missing DPD should not automatically become zero, because zero means the account is known to be current. Preserve the unknown state with a nullable integer dtype:

```python
loans["days_past_due"] = loans["days_past_due"].astype("Int64")
loans["dpd_missing"] = loans["days_past_due"].isna()
```

Fill values only when the replacement has a defined business meaning. For example, if a particular extract defines missing undrawn amount as no undrawn commitment, the implementation might be:

```python
loans["undrawn_amount_output"] = loans["undrawn_amount"].fillna(0)
```

But the original column should often be retained so the analyst can distinguish sourced zero from substituted zero.

Aggregations commonly skip missing numeric values. That can be useful, but it means a mean or sum may be calculated from fewer observations than the row count suggests. Pair measures with non-missing counts when completeness matters.

`NaT` is the datetime missing marker; `pd.NA` is pandas' scalar for nullable extension dtypes; Python `None` often appears in object data; NumPy `NaN` is common in floating-point columns. `isna()` provides one consistent detection interface across them.

### Never confuse [NaN] and [None]

**NaN** - a floating-point missing marker commonly used in NumPy-backed numeric data.

---

**None** - Python's null object, often found in object-typed data; pandas generally detects both with `isna()`.

### Permanent rule

Preserve the distinction between unknown and known zero unless the business definition explicitly equates them.

### Permanent trap

Using `series == np.nan` to find missing values. Missing markers are not reliably found by ordinary equality; use `isna()`.
