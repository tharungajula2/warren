### Core mechanism

| Failure | What happened | Credit example |
| :--- | :--- | :--- |
| Target leakage | Predictor contains information created by or after the outcome | Post-default collection status used to predict default |
| Time leakage | Future information enters an earlier prediction | Month-end bureau field used for a decision made mid-month |
| Train-test contamination | Evaluation information influences fitting or selection | Same borrower appears across train and test with overlapping history |
| Overfitting | Model learns unstable idiosyncrasies | Deep tree isolates tiny borrower pockets |
| Underfitting | Model cannot represent real structure | Single linear effect where risk is strongly nonlinear |
| Regime shift | Future data-generating process changes | New underwriting policy or recession changes borrower mix and outcomes |

Excellent development performance

### Formula

```text
Expected generalisation error = average loss on new observations from the deployment process
```

### Permanent rule

Every feature must exist at the prediction timestamp, and every performance claim must be measured on data genuinely outside the decisions used to build the model.

### Never confuse [Data leakage] and [Overfitting]

**Data leakage** - unavailable or evaluation information enters model development, creating artificial signal.

---

**Overfitting** - the model uses legitimate training information but learns noise that does not generalise.

### Permanent trap

Diagnosing every OOT deterioration as overfitting. A clean model can deteriorate because portfolio mix or macro conditions changed, while a leaked model can look stable until the leaked signal disappears operationally.

### Jurisdiction variants

No delta. Leakage and generalisation are statistical concepts.
