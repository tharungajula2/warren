For instance, to summarize a loan portfolio, one might compute total outstanding by product:
```sql
SELECT ProductType, SUM(OutstandingBalance) AS TotalBalance
FROM Loans
GROUP BY ProductType;
```
This splits the data by each `ProductType` (group), then `SUM` is applied per group. Often combined with `COUNT`, `AVG`, etc. To filter on aggregate values (e.g. only products with large totals), use `HAVING`:
```sql
SELECT ProductType, SUM(OutstandingBalance) AS TotalBalance
FROM Loans
GROUP BY ProductType
HAVING SUM(OutstandingBalance) &gt; 1000000;
```
This returns only products where the summed balance exceeds a threshold. Note `HAVING` comes after grouping, unlike `WHERE` which filters rows before grouping.

### Permanent rule

All non-aggregated columns in the `SELECT` list must appear in `GROUP BY`.

### Permanent trap

Omitting required `GROUP BY` columns (or aggregating every column) causes SQL errors. Also, forgetting `HAVING` conditions when needed means large groups won’t be filtered.

### Never confuse

**WHERE** — filters individual rows before grouping.
---
**HAVING** — filters entire groups after aggregation.

### Jurisdiction variants

**No delta.** Aggregation with `GROUP BY`/`HAVING` is consistent across SQL dialects.
