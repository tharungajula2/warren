### Core mechanism

Encode key assumptions immediately after the transformation that could break them:

```python
import numpy as np
import pandas as pd

key = ["account_id", "reporting_date"]
assert not portfolio.duplicated(key).any()
assert portfolio["reporting_date"].eq(pd.Timestamp("2026-08-31")).all()
assert portfolio["account_id"].notna().all()
```

Tie controlled totals before and after pure enrichment:

```python
before_balance = base["outstanding_balance"].sum()
after_balance = portfolio["outstanding_balance"].sum()

assert np.isclose(before_balance, after_balance, rtol=0, atol=0.01)
```

Test expected relationships rather than only end totals. If the August portfolio should contain the same account population as the base snapshot, compare keyed sets or row counts as appropriate. If a classification has an UNKNOWN category, assert that its count is reviewed rather than silently dropped.

Separate code from changing parameters. A reporting date can be a single named variable used throughout the script instead of being retyped in five filters:

```python
reporting_date = pd.Timestamp("2026-08-31")
output_file = f"credit_portfolio_&#123;reporting_date:%Y_%m_%d&#125;.csv"

portfolio.to_csv(output_file, index=False)
```

Reproducibility also requires version-controlled scripts, known package dependencies, controlled input locations, and deterministic sorting where output order matters. Do not rely on notebook execution order that cannot be reproduced from a clean start.

Testing here is execution craft, not a replacement for DAT's formal test-pack or UAT ownership. TEC proves that the analyst code enforces its declared assumptions and produces a stable output.

### Where it sits

```text
Upstream:   Completed SQL or pandas transformation · Control expectations
This:       Assertions · Tie-outs · Deterministic parameters · Reproducibility
Downstream: Governed dataset · Reporting · QNT analysis · Review and reuse
```

### Never confuse [Assertion] and [Data-quality rule]

**Assertion** - executable code that fails when an expected condition is violated during the analysis.

---

**Data-quality rule** - the governed expectation defining what data condition should hold and how a failure is handled.

### Permanent rule

Every transformation that can change grain, population, dates, or controlled amounts should be followed by an executable check of the property that must remain true.

### Permanent trap

Running a notebook successfully and calling it reproducible. Hidden state, manual cell order, untracked inputs, or unpinned dependencies can prevent the same code from producing the same result later.

### Jurisdiction variants

No delta. Testing and reproducibility mechanics do not vary by regulator.
