Testing is essential: write unit tests or assertions to verify code correctness. For example, test that a summary statistic matches a known result or that two different methods yield the same total. A single risk number untested is a hidden model risk. Frameworks like `pytest` can automate tests.

Finally, use version control (e.g. Git). Commit code regularly with meaningful messages. This allows rollback, review (code audit), and collaboration. Store scripts in a repository (internal or GitHub Enterprise). Each change to analysis code should be tracked like financial model changes.

<Rule label="PERMANENT RULE">
Pin and document dependencies, and always run tests after making changes.
</Rule>

<Trap label="PERMANENT TRAP">
Copying code around or running analyses manually without scripts. Avoid “lone excel-like” scripts with no version history or tests.
</Trap>

<NeverConfuse a="Unit Test" b="Version Control Commit">
**Unit Test** — automated check of a small code piece against expected output.
---
**Version Control Commit** — a snapshot of code changes saved in a repository.
</NeverConfuse>

<Rule label="NO DELTA">
**No delta.** These software best practices apply to analysts worldwide.
</Rule>
