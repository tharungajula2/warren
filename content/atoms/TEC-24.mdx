### Core mechanism

Attach facility attributes to an account-level portfolio through a one-to-one account mapping and many-to-one facility lookup:

```python
portfolio = portfolio.merge(
    loan_accounts[["account_id", "facility_id"]],
    on="account_id",
    how="left",
    validate="one_to_one",
)

portfolio = portfolio.merge(
    facilities[["facility_id", "customer_id", "product_type"]],
    on="facility_id",
    how="left",
    validate="many_to_one",
)
```

`validate` turns an assumption into an executable assertion. If `facilities` unexpectedly contains duplicate `facility_id` values, the second merge fails rather than silently multiplying account rows.

For a many-side table such as the repayment schedule, aggregate before merging:

```python
september_due = (
    schedule.loc[
        schedule["due_date"].ge("2026-09-01")
        &amp; schedule["due_date"].lt("2026-10-01")
    ]
    .groupby("account_id", as_index=False)
    .agg(scheduled_amount_sep=("scheduled_amount", "sum"))
)

portfolio = portfolio.merge(
    september_due,
    on="account_id",
    how="left",
    validate="one_to_one",
)
```

Check row count and portfolio balance before and after any enrichment that should preserve account grain.

`DataFrame.join()` is convenient mainly for index-based joining; `merge()` makes column keys, join type, and cardinality validation more explicit for lending-table work.

### Where it sits

```text
Upstream:   DataFrame grain · Key uniqueness · Child-table aggregation
This:       merge · Join type · validate · Fan-out prevention
Downstream: Enriched portfolio · As-of matching · Portfolio summaries
```

### Never confuse [merge] and [join]

**merge** - database-style joining with explicit column or index keys and cardinality validation options.

---

**join** - a DataFrame convenience method oriented toward joining on indexes, though it can also use a key column.

### Permanent rule

Use `validate` whenever the expected merge cardinality is known, and recheck controlled totals after enrichment.

### Permanent trap

Relying on `drop_duplicates()` after a fan-out merge. It can delete symptoms without restoring the correct measure grain or identifying the bad key relationship.

  a="It asserts that each left-side row may share a key with others but the right-side key must be unique, preventing an unexpected many-to-many multiplication."
