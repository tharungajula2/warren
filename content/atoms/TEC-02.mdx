### Core mechanism

Suppose the analyst needs active accounts in the August 2026 month-end snapshot with positive drawn exposure:

```sql
SELECT
    account_id,
    reporting_date,
    outstanding_balance,
    days_past_due
FROM loan_snapshots
WHERE reporting_date = '2026-08-31'
  AND status = 'ACTIVE'
  AND outstanding_balance &gt; 0
ORDER BY account_id;
```

The order of the written predicates does not create a business hierarchy; together they define the row population. Be explicit about inclusions and exclusions. A condition on a date, status, currency, or product can materially change the denominator of every later portfolio measure.

Use parentheses when `AND` and `OR` are mixed so the intended logic is visible:

```sql
SELECT account_id, status, days_past_due
FROM loan_snapshots
WHERE reporting_date = '2026-08-31'
  AND (
      status = 'ACTIVE'
      OR days_past_due &gt; 0
  )
ORDER BY account_id;
```

For date-time columns, prefer closed-open ranges rather than assuming every row sits exactly at midnight. The general pattern is `timestamp &gt;= start` and `timestamp &lt; next_start`.

`ORDER BY` controls presentation or deterministic ranking input; it does not define table storage order. Without it, the database may return rows in any convenient order.

### Where it sits

```text
Upstream:   Grain · Reporting date · Business population rule
This:       SELECT · WHERE · Predicate logic · ORDER BY
Downstream: CASE classifications · Aggregation · Joins
```

### Permanent rule

Write filters so another analyst can state the resulting population in one sentence without guessing at operator precedence or hidden defaults.

### Never confuse [WHERE] and [ORDER BY]

**WHERE** - changes which rows are included.

---

**ORDER BY** - changes the sequence of returned rows without changing membership.

### Permanent trap

Treating a query that runs as proof that the population is right. SQL validates syntax and types, not the business meaning of the filter.

### Jurisdiction variants

No delta. SQL filtering semantics do not vary by regulator.

<Recall
  q="What does `WHERE` control in a loan-book query?"
  a="It controls population membership; every included or excluded row changes the universe available to later calculations."

<Recall
  q="Why add parentheses around mixed `AND` and `OR` conditions?"
  a="They make precedence explicit and prevent a syntactically valid query from applying a broader or narrower population rule than intended."

<Recall
