  The relational model organizes data into structured tables (relations) with
  rows and columns, using keys to connect data across tables. Each table
  represents an entity (e.g. **Loan**, **Customer**), rows are records, and
  columns are fields. A **primary key** is a unique identifier for each row
  (cannot be NULL). A **foreign key** in one table references a primary key in
  another to link related data (e.g. an *Account* table has a CustomerID
  referencing the *Customer* table). This design avoids redundancy (no repeated
  customer details in every loan row) and enforces data integrity through
  relationships.

The *Loan Book* in banking is not a single table: loans have borrowers, products, schedules, etc. Each aspect lives in its own table with keys linking them. For example, a *Facility* table may link to multiple *Account* rows (one-to-many), and accounts link to *Exposure* or *Transaction* tables. Keys ensure SQL queries join these tables reliably.

```text
+-----------+       +----------+       +-------------+
| Facility  |       | Account  |       | Transaction |
+-----------+       +----------+       +-------------+
| FacilityID| 1   M | AccountID| 1   M | TransID     |
| ...       |-------| FacID FK |-------| AccountID FK|
+-----------+       +----------+       +-------------+
```

### Permanent rule

Every table should define a **primary key** column(s) that uniquely identifies each row.

### Permanent trap

Putting unrelated data in one wide table (no keys) or not enforcing uniqueness can lead to corruption (e.g. duplicate loan records).

### Never confuse

**Primary Key** — uniquely identifies a row in its table (no duplicates, no NULLs).
---
**Foreign Key** — references a primary key in another table, establishing a link.

<Recall
  q="What uniquely identifies a row in a relational table?"
  a="The primary key."
/>

<Recall
  q="How do tables link to each other?"
  a="By foreign keys referencing primary keys."
/>
