### Core mechanism

```text
Start from defined target requirement
    ↓
Identify candidate source systems and datasets
    ↓
Profile grain, keys, population and history
    ↓
Trace upstream transformations and authority
    ↓
Assess quality, timing and control evidence
    ↓
Select governed source path and record gaps
```

| Sourcing question | Defect prevented |
| :--- | :--- |
| Is this source authoritative for the concept? | Choosing a convenient downstream copy over the governed source |
| What is the row grain? | Duplicate joins and accidental aggregation |
| Which key links to other datasets? | Orphan records and many-to-many multiplication |
| What history is retained? | Inability to reproduce prior reporting dates |
| Is the field raw or already transformed? | Applying the same business rule twice |
| When is it available? | Missing reporting cut-off or using stale data |
| What known defects exist? | Building a new report on an uncontrolled weakness |

ETL sourcing analysis is not code design. It establishes the business and data facts that developers need before implementing extraction and transformation logic.

### Where it sits

```text
Upstream:   Requirements · Golden sources · Lineage · Metadata
This:       Source discovery and sourcing analysis
Downstream: Source-to-target mapping · ETL build · Test data · Impact assessment
```

### Never confuse [Source discovery] and [Source selection]

**Source discovery** - investigates all plausible sources and their characteristics.

---

**Source selection** - the governed decision on which path satisfies the requirement. Selection without discovery can institutionalise the first convenient answer.

### Permanent rule

The chosen source path must be explainable in terms of authority, grain, timing, history and quality, not personal familiarity with a system.

### Permanent trap

Beginning the mapping with target columns and asking developers where they can find something similar. Similar field names are weak evidence of equivalent business meaning.

### Jurisdiction variants

**No delta.** Source analysis is a delivery practice independent of the reporting jurisdiction.

<Recall
  q="Why must analysts determine whether a source field is already transformed?"
  a="Applying a regulatory or business rule again can double-transform the value and create a plausible but incorrect result."

<Recall
  q="Why does history matter during sourcing?"
  a="Regulatory and risk reports must often be reproducible at prior reference dates; a current-state source may not preserve the historical values used at filing time."
