For example, instead of nesting multiple subqueries, use a CTE:
```sql
WITH RecentLoans AS (
  SELECT LoanID, Principal, SaleDate
  FROM Loans
  WHERE SaleDate &gt; '2025-01-01'
)
SELECT COUNT(*) FROM RecentLoans WHERE Principal &gt; 100000;
```
This defines `RecentLoans` once, then queries it. A subquery approach would nest the SELECT inside another SELECT.

```text
WITH cte_table AS (
    +------------------+
    | (complex query)  |
    +------------------+
)
SELECT * FROM cte_table;
```

```text
SELECT * FROM (
    +------------------+
    | (complex query)  |
    +------------------+
) AS sub;
```

### Permanent rule

A CTE must be immediately followed by a SELECT (or INSERT/UPDATE/DELETE) that references it.

### Permanent trap

A CTE’s scope is limited to one statement; it cannot be reused outside. Also, avoid overly deep nesting – break logic into multiple CTEs if needed.

### Never confuse

**Subquery** — an unnamed SELECT inside another query (inline, not reusable).

---

**CTE (WITH)** — a named temporary table defined for one query (improves clarity and reuse).

### Jurisdiction variants

**No delta.** CTEs and subqueries are standard SQL features everywhere.
