### Core mechanism

Check account-month uniqueness explicitly rather than assuming the default integer index proves anything:

```python
key = ["account_id", "reporting_date"]

duplicates = loans.duplicated(key, keep=False)
print(loans.loc[duplicates, key].sort_values(key))
```

The default `RangeIndex` merely labels row positions. You may set a meaningful index when it makes repeated operations clearer, but doing so does not enforce uniqueness by itself:

```python
indexed = loans.set_index(["account_id", "reporting_date"])
print(indexed.index.is_unique)
```

Dtypes determine behaviour. `reporting_date` should be datetime-like for period operations; `outstanding_balance` numeric for arithmetic; `account_id` often string; low-cardinality labels such as `status` may be categorical when useful. Nullable integer types can represent missing DPD without forcing the entire column to floating point.

```python
loans["account_id"] = loans["account_id"].astype("string")
loans["days_past_due"] = loans["days_past_due"].astype("Int64")
loans["status"] = loans["status"].astype("category")
```

Changing the index can affect alignment in later arithmetic and assignment because pandas often aligns by labels. Resetting or merging without understanding that alignment can create missing values or unexpected row order even when array lengths match.

### Never confuse [DataFrame index] and [Business key]

**DataFrame index** - pandas row labels used for selection and alignment.

---

**Business key** - the field or fields that uniquely identify a record at the declared lending grain.

### Permanent rule

Track business grain independently of the DataFrame index, and validate dtypes before relying on arithmetic, dates, or joins.

### Permanent trap

Treating a unique `RangeIndex` as evidence that the lending records are unique. Every DataFrame can have unique row positions while containing duplicated account-month business keys.
