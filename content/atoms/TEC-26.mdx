### Core mechanism

Convert date columns before using them:

```python
import pandas as pd

portfolio["reporting_date"] = pd.to_datetime(portfolio["reporting_date"])
portfolio["origination_date"] = pd.to_datetime(portfolio["origination_date"])
```

Create month-level period labels for reporting and vintage:

```python
portfolio["reporting_month"] = portfolio["reporting_date"].dt.to_period("M")
portfolio["vintage_month"] = portfolio["origination_date"].dt.to_period("M")
```

Months-on-book is the difference between those monthly periods. A clear integer implementation is:

```python
reporting = portfolio["reporting_month"]
origination = portfolio["vintage_month"]

portfolio["mob"] = (
    (reporting.dt.year - origination.dt.year) * 12
    + reporting.dt.month
    - origination.dt.month
)
```

This counts calendar month boundaries. If the business definition treats origination month as MOB 0, the result is already aligned to that convention. If another convention is specified, adjust the final label deliberately rather than changing the date arithmetic invisibly.

Use date ranges or period comparisons for population selection:

```python
august_payments = payments.loc[
    payments["payment_date"].ge("2026-08-01")
    &amp; payments["payment_date"].lt("2026-09-01")
].copy()
```

Period labels are useful for grouping and cohort views, while timestamps remain useful for exact effective-date matching. Keep both when both meanings are needed.

### Never confuse [Timestamp] and [Period]

**Timestamp** - a specific point in time such as 2026-08-31.

---

**Period** - a labelled interval such as August 2026, useful for cohort and reporting-month grouping.

### Permanent rule

Derive vintage and MOB from typed dates or periods, never from formatted text or days divided by an assumed month length.

### Permanent trap

Subtracting two dates, dividing days by 30, and calling the result MOB. Calendar months vary in length and that shortcut can misclassify tenure.
