### Core mechanism

| Mapping column | What it must establish |
| :--- | :--- |
| Requirement ID | Why the target field exists and which approved need it satisfies |
| Target field | Name, definition, datatype, grain and mandatory status |
| Source | System, object, field and authoritative-source status |
| Join / key | How source records connect without duplication or loss |
| Filter | Which records enter or leave the target population |
| Transformation | Derivation, aggregation, sign, unit, date or currency treatment |
| Reference mapping | Governed code conversion and version |
| Null / default logic | What happens when source data is absent or invalid |
| Control | Validation or reconciliation that proves implementation |
| Version | Effective date and approved change history |

```text
Approved requirement
    ↓
Governed source and grain
    ↓
Join + filter + transformation + reference mapping
    ↓
Target field at defined grain
    ↓
Control and traceability evidence
```

A mapping should avoid hidden logic such as "standard treatment" unless that treatment is separately controlled and versioned. If logic depends on a lookup table, the lookup source and effective version belong in the specification.

### Where it sits

```text
Upstream:   Requirements · Source analysis · Metadata · Reference data
This:       Field-level source-to-target contract
Downstream: ETL development · Test packs · UAT · Downstream validation · Lineage
```

### Never confuse [Mapping rule] and [Business definition]

**Mapping rule** - how a defined concept is implemented from source fields into a target.

---

**Business definition** - what the concept means. A technically perfect mapping to the wrong definition is still wrong.

### Permanent rule

Every target field that matters must be traceable to an approved requirement and governed source logic, including handling of missing and exceptional cases.

### Permanent trap

Documenting only Source Field -&gt; Target Field. Most material reporting defects live in the omitted joins, filters, transformations, reference mappings and defaults.

### Jurisdiction variants

**No delta.** Mapping practice is universal; target templates and taxonomies differ by jurisdiction.
