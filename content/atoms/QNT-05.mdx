### Core mechanism

| Consequence of rarity | Credit effect |
| :--- | :--- |
| Majority dominance | Overall accuracy can be high even with poor default detection |
| Sparse-event uncertainty | Default-rate and coefficient estimates become noisy |
| Thin segments | Some grades or bins contain too few defaults for stable estimation |
| Threshold sensitivity | Small cutoff changes can move many non-defaults and few defaults |
| Metric dependence | Precision changes strongly with prevalence even when ranking ability is unchanged |

```text
100,000 loans
    ↓
1,000 defaults + 99,000 non-defaults
    ↓
Predict every loan non-default
    ↓
99 percent accuracy
    ↓
Zero defaults detected
```

Rare-event learning is an information problem, not merely a data-volume problem. Ten million non-defaults cannot substitute perfectly for a small number of defaults because the event observations carry the information about how the default class differs.

### Where it sits


### Formula

```text
Default prevalence = number of defaults / total labelled observations
Accuracy = correct predictions / total predictions
```

### Permanent rule

Always interpret classification performance together with event prevalence. A metric that ignores class composition can hide failure on the event the credit model exists to distinguish.

### Never confuse [Rare event] and [Small dataset]

**Rare event** - the outcome of interest is scarce relative to the other class.

---

**Small dataset** - the total number of observations is limited. A dataset can be enormous and still contain too few defaults for a narrow segment.

### Permanent trap

Using raw accuracy as the headline measure for a default model. In an imbalanced portfolio, a trivial majority-class rule can achieve impressive accuracy without useful risk discrimination.

### Jurisdiction variants

No delta. Class imbalance is a property of the data-generating process, not the regulator.
