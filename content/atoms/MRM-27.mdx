### Core mechanism

| Validation lens | Validator asks |
| :--- | :--- |
| Generalisation | Does performance persist outside development data and familiar conditions? |
| Overfitting | Has the model learned noise rather than durable relationships? |
| Drift | Are inputs, outputs or relationships changing after deployment? |
| Robustness | Do small plausible changes cause unstable outputs? |
| Subgroup performance | Are weaknesses concentrated in relevant populations? |
| Explainability | Are explanations sufficiently faithful and stable for their purpose? |
| Dynamic behaviour | Can retraining or automatic updates alter the governed model? |
| Stress / challenge testing | What happens under unusual or deliberately difficult inputs? |

```text
Development evidence
    ↓
Independent challenge
    ↓
Generalisation + robustness evidence
    ↓
Drift + subgroup analysis
    ↓
Explainability / behaviour challenge
    ↓
Validation opinion + monitoring conditions
```

Red-teaming intentionally seeks harmful, unstable or policy-breaking behaviour under realistic risk scenarios. It complements ordinary validation. This pack owns the validator's use of evidence, not ML mathematics or test derivation.

### Where it sits

```text
Upstream:   AI/ML governance · Independent validation · Outcomes analysis
This:       AI/ML-specific validation

```

### Permanent rule

Average accuracy is weak evidence when failure concentrates in edge cases, subgroups or changed environments. Validation must look for where the model breaks.

### Never confuse [Drift] and [Overfitting]

**Drift** - live data or the relationship between inputs and outcomes changes after development.

---

**Overfitting** - the model learned development-specific noise or patterns that fail to generalise even without genuine external change.

### Permanent trap

Validating the explanation method but not the model behaviour it claims to explain. A plausible explanation can still be unstable, incomplete or unfaithful.

<Recall
  q="Why can strong average test accuracy still leave serious AI/ML model risk?"
  a="Average performance can hide failures in subgroups, edge cases or changed conditions. Validation must test generalisation, robustness and where errors concentrate."
/>

<Recall
  q="How does drift differ from overfitting?"
  a="Drift means the live environment or relationship moved; overfitting means the original model learned patterns that never generalised reliably."
/>

<Recall
  q="What role does red-teaming play?"
  a="It deliberately searches for failure under challenging inputs or interactions, supplementing ordinary performance and robustness testing rather than replacing the validation work programme."
