  SQL window functions perform calculations across rows related to the current
  row without collapsing groups. For example, `ROW_NUMBER()` assigns a
  sequential number to rows in a partition, while `RANK()` assigns equal numbers
  to tied values. `LAG(col,1) OVER(...)` gets the previous row’s value, and
  `LEAD` gets the next row’s. You must include an `OVER(PARTITION BY ... ORDER
  BY ...)` clause. Window functions are ideal for credit roll-forwards: e.g.
  computing a loan delinquency at each period and comparing to the prior period
  using `LAG` or cumulative sums.

Example: to assign row numbers within each product line:
```sql
SELECT LoanID, ProductType,
       ROW_NUMBER() OVER (PARTITION BY ProductType ORDER BY StartDate) AS LoanSeq
FROM Loans;
```
Here `ROW_NUMBER` restarts count for each `ProductType` group. `RANK()` would give the same sequence number to ties.

### Permanent rule

Always specify an `ORDER BY` inside the window if using `LAG`, `LEAD`, or ranking; otherwise the result order is arbitrary.

### Permanent trap

Forgetting `PARTITION BY` leads to global ranking instead of per-group. Also, not knowing `RANK()` vs `ROW_NUMBER()` can miscount ties.

### Never confuse

**ROW_NUMBER()** — assigns unique sequential numbers (1,2,3...).
---
**RANK()** — assigns the same rank to ties (1,2,2,4...).

### Jurisdiction variants

**No delta.** Window function syntax is SQL-standard (though exact function names may vary slightly by dialect).
