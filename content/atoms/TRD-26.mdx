The trade lifecycle is the controlled transformation of an agreed transaction into legally, operationally and financially completed obligations. Different products use different infrastructure, but the core stages recur.

Execution creates the commercial agreement. Trade capture records economics in the institution’s systems. Enrichment adds reference data such as legal entity, book, account, settlement instructions and clearing attributes. Validation checks that mandatory fields and eligibility rules are satisfied. Confirmation or affirmation establishes that counterparties agree the terms.

Clearing may follow for eligible derivatives or securities markets. Once accepted, the trade can become a cleared position with CCP margin obligations. Settlement moves cash, securities or other deliverables. For longer-lived derivatives, the lifecycle then continues through resets, fixings, coupons, option exercises, margin calls, collateral substitutions and valuations.

Regulatory reporting can occur at multiple points and is not the same as internal booking. A trade can be correctly settled but incorrectly reported if identifiers, timestamps or counterparty classifications are wrong. Conversely, a reporting acknowledgement does not prove economic settlement.

Events change the trade after booking. A partial termination reduces notional. A novation changes a counterparty. An amendment changes terms. A compression exercise may replace many trades with fewer economically equivalent ones. Corporate actions can alter securities positions. Every event requires lineage from the original trade state to the new state.

The most useful BA model is state plus event. Instead of treating a trade as one database row, treat it as an object whose state changes through authorised events. Each downstream system should know whether it consumes original economics, current economics, event history or settlement outputs.

Breaks occur when two systems are correct about different states. The control question is therefore: what event has each system processed, using what effective timestamp and source?

```text
Execute
   |
Capture
   |
Enrich / validate
   |
Confirm / affirm
   |
Clear if applicable
   |
Settle
   |
+--&gt; value / margin
+--&gt; report
+--&gt; lifecycle events
         |
         v
maturity / termination / close-out
```

### Permanent rule

A trade lifecycle is a sequence of state changes, not a single booking event.

### Permanent trap

Calling a trade “done” once front office has booked it.

### Never confuse

**Trade state** — the current contractual and operational condition of a transaction.

---

**Lifecycle event** — an authorised occurrence that changes, settles or terminates part of that state.

### Jurisdiction variants

**No delta.**
