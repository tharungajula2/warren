### Core mechanism

| Source | Failure mode | Typical control response |
| :--- | :--- | :--- |
| Data | Wrong, incomplete, biased, stale or unrepresentative inputs | Repair lineage, quality or sampling |
| Assumptions | Simplifications cease to hold | Challenge, constrain or revise assumptions |
| Methodology | Model form does not represent the problem adequately | Redesign or redevelop |
| Implementation | Code, configuration or interface differs from approved design | Correct implementation and retest |
| Use | Output is misinterpreted or applied outside intended scope | Restrict use, train users, reapprove |
| Environment | Population, behaviour or relationships change | Monitor, recalibrate or redevelop |
| Governance | Weak challenge allows known limitations to persist | Escalate, remediate, strengthen control |

The categories can interact:

Data shift → assumption no longer holds → calibration deteriorates → users apply stale output → losses increase

Root-cause analysis therefore matters more than attaching a generic "model underperformance" label.

### Ownership

| Role | Responsibility |
| :--- | :--- |
| Developer / owner | Controls design, data and implementation risks |
| Model user | Controls scope, interpretation and use risk |
| MRM / validation | Challenges all sources and their interactions |
| Internal audit | Assesses whether the control framework catches them |

### Permanent rule

A performance symptom is not a root cause. Diagnose where the failure entered before choosing the remedy.

### Never confuse [Implementation error] and [Model limitation]

**Implementation error** - the production system does not execute the approved model correctly.

---

**Model limitation** - the approved model itself has a known boundary, approximation or uncertainty even when implemented exactly as designed.

### Permanent trap

Responding to every poor result with recalibration. Recalibration may repair stale parameter levels; it does not fix corrupted data, bad code, conceptual misspecification or misuse.

### Jurisdiction variants

No delta. Data, design, implementation, use and environmental change are universal sources even though regulators express them with different terminology.
