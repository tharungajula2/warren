### Core mechanism

Start by exposing the previous DPD for each account:

```sql
WITH history AS (
    SELECT
        account_id,
        reporting_date,
        days_past_due,
        LAG(days_past_due) OVER (
            PARTITION BY account_id
            ORDER BY reporting_date
        ) AS prior_dpd
    FROM loan_snapshots
)
SELECT
    account_id,
    reporting_date,
    days_past_due,
    prior_dpd,
    CASE
        WHEN prior_dpd IS NULL THEN 'FIRST_OBSERVATION'
        WHEN days_past_due = 0 AND prior_dpd &gt; 0 THEN 'CURE'
        WHEN days_past_due &gt; prior_dpd THEN 'WORSEN'
        WHEN days_past_due &lt; prior_dpd THEN 'IMPROVE'
        ELSE 'UNCHANGED'
    END AS dpd_movement
FROM history;
```

A first-delinquency date can be derived without collapsing the history by using a conditional window minimum:

```sql
SELECT
    account_id,
    reporting_date,
    days_past_due,
    MIN(CASE WHEN days_past_due &gt; 0 THEN reporting_date END) OVER (
        PARTITION BY account_id
    ) AS first_delinquency_date
FROM loan_snapshots;
```

Consecutive delinquency needs an explicit sequence rule. One practical approach creates a reset group whenever the account returns to current, then counts rows inside each delinquent run. That logic assumes observations are regular enough that consecutive rows represent consecutive reporting periods. If a month is missing, row adjacency is not the same as calendar continuity and the gap must be detected.

### Permanent rule

A sequence metric is valid only if the observation order and cadence support the meaning of "previous" and "consecutive."

### Never confuse [Prior row] and [Prior period]

**Prior row** - the immediately preceding record in the ordered data.

---

**Prior period** - the required earlier calendar observation, which may be missing from the data.

### Permanent trap

Treating adjacent rows as consecutive months without checking for gaps. An account with June and August observations has a prior row but no July observation.

### Jurisdiction variants

No delta. DPD sequence coding does not vary by regulator.
