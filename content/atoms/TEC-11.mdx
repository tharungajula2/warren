### Core mechanism

To compare each account with its prior reporting date, partition by account and order chronologically:

```sql
SELECT
    account_id,
    reporting_date,
    outstanding_balance,
    LAG(outstanding_balance) OVER (
        PARTITION BY account_id
        ORDER BY reporting_date
    ) AS prior_balance
FROM loan_snapshots;
```

`LAG` preserves every snapshot row while exposing the previous value. `LEAD` does the same for the next observation. Ranking functions such as `ROW_NUMBER` also operate over a partition and order rather than collapsing the data.

Running calculations require attention to the frame. For a cumulative amount by account:

```sql
SELECT
    account_id,
    payment_date,
    payment_amount,
    SUM(payment_amount) OVER (
        PARTITION BY account_id
        ORDER BY payment_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_paid
FROM payments;
```

The explicit `ROWS` frame says to include all prior physical rows in the ordered account history. Omitting a frame can invoke engine defaults that behave differently when order values tie.

Window functions assume the ordering column can establish the sequence needed by the business question. If an account can have multiple records on the same reporting date, add a deterministic tie-breaker or first resolve the duplicate grain problem.

### Permanent rule

For every window expression, be able to state the partition, the order, and whether tied order values can occur.

### Never confuse [GROUP BY] and [Window function]

**GROUP BY** - collapses many input rows into one row per group.

---

**Window function** - calculates across related rows while preserving the original row grain.

### Permanent trap

Using `LAG` without a deterministic order. The database may return a prior row, but not necessarily the prior business observation you intended.

<Recall
  q="What does `PARTITION BY account_id` do in a loan-history window?"
  a="It restarts the calculation for each account so values from different borrowers or accounts cannot enter the same sequence."
/>

<Recall
  q="Why can an explicit window frame matter for a running total?"
  a="It defines exactly which ordered rows contribute, avoiding surprises from engine defaults when order values tie."
/>

<Recall
  q="How is a window calculation different from aggregation?"
  a="A window adds context such as prior or cumulative values while keeping each original observation row; aggregation changes the result grain."
