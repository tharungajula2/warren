### Core mechanism

```text
Approved specification
    ↓
Code / configuration
    ↓
Independent implementation checks
    ↓
Controlled production release
    ↓
Versioned execution
    ↓
Reproducible output
```

| Control | What it prevents |
| :--- | :--- |
| Source control | Undocumented code changes |
| Unique version | Ambiguity about which model was used |
| Peer / independent code review | Logic and implementation errors |
| Test cases | Silent calculation defects |
| Development-production reconciliation | Different transformations or parameters |
| Dependency pinning | Uncontrolled library or service changes |
| Release approval | Unauthorised production updates |
| Execution logs | Inability to reconstruct model behaviour |

Reproducibility means that with the governed model version, relevant inputs and environment, the institution can reconstruct or adequately evidence how the output was produced. For stochastic models, reproducibility may require seeds, configuration and retained run metadata rather than identical output in every context.

### Where it sits

```text
Upstream:   Method specification · Data lineage
This:       Executable model and version control
Downstream: Developer testing · Validation · Deployment · Change control
```

### Ownership

| Role | Responsibility |
| :--- | :--- |
| Developer | Implements and unit-tests approved logic |
| Technology / MLOps | Controls environments, release and dependencies |
| Model owner | Ensures governed version matches authorised use |
| Validation | Tests implementation consistency and reproducibility |

### Permanent rule

A model version is part of the model identity. Change code, parameters, transformations or material configuration and the governance question is whether you still have the approved model.

### Never confuse [Methodology validation] and [Implementation verification]

**Methodology validation** - asks whether the model concept and assumptions are appropriate.

---

**Implementation verification** - asks whether the executable system faithfully performs that approved concept.

### Permanent trap

Validating a development notebook and assuming production is identical. Differences in code, data transformation, libraries, interfaces or configuration can create a new failure mode after technical validation.

### Jurisdiction variants

No delta. Implementation assurance and reproducibility are general controls; exact technology standards vary by institution rather than by the core MRM principle.

<Recall
  q="Why is versioning an MRM control rather than just an IT practice?"
  a="Model approval and validation attach to a defined implementation. Without version identity, the institution cannot know whether the output came from the model that was actually challenged and authorised."
/>

<Recall
  q="What does reproducibility require for a stochastic model?"
  a="Enough retained code, configuration, data lineage and run metadata to reconstruct the governed process and explain the output; exact deterministic replication may not be the relevant standard."
