### Core mechanism

```text
Validation mandate
    ↓
Independent access to model, data and documentation
    ↓
Critical analysis and testing
    ↓
Reliability + limitations + required actions
    ↓
Validation opinion
    ↓
Approval decision
```

| Independence dimension | What good looks like |
| :--- | :--- |
| Organisational | Validation is not controlled by model development or use |
| Incentives | Validator is not rewarded for getting the model approved |
| Expertise | Validator can understand and challenge the model's methods |
| Access | Validator can obtain data, code, documentation and users |
| Standing | Findings can reach decision-makers and delay or restrict use |
| Scope | Validation can extend testing when developer evidence is weak |

Timing should be risk-based. First-use validation is the normal control point; material changes, emerging weaknesses or changing conditions can trigger renewed validation. A fixed calendar alone is insufficient because a stable low-risk model and a rapidly changing material model should not receive identical attention.

### Where it sits

```text
Upstream:   Developer evidence · Model tier · Governance roles
This:       Independent validation mandate and timing
Downstream: Validation work programme · Findings · Approval
```

### Permanent rule

Validation must be able to reach an unfavourable conclusion without organisational pressure to approve the model.

### Never confuse [Validation independence] and [Physical separation]

**Validation independence** - sufficient objectivity, expertise, authority and freedom from conflicting incentives to challenge the model.

---

**Physical separation** - different desks, teams or reporting lines. It may support independence but does not guarantee it.

### Permanent trap

Using an annual validation calendar as proof of control. Frequency should respond to purpose, materiality, methodology, model change, data limitations and emerging evidence.

### Jurisdiction variants

| Jurisdiction | Timing / frequency | Independence / status |
| :--- | :--- | :--- |
| US | Scales with use, materiality, methodology, change, data limits and constraints. | Usually pre-use; urgent early use needs limits, stakeholder communication and heightened monitoring. |
| UK | Proportionate to model risk. | Principle 4: independent validation, effective challenge, separation from development/use. |
| EU | Ongoing assessment commensurate with prudential-model risk. | Independent validation embedded in CRR/ECB governance. |
| IN | Proposed pre/post-deployment, after modifications/triggers and periodically. | All models; draft as at August 2026, not final. |

<Recall
  q="Why can a validator be organisationally separate yet not truly independent?"
  a="Separation fails if incentives, access or escalation power still discourage challenge. Independence requires the practical ability to reach and defend an adverse conclusion."
/>
