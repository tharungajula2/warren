For regulatory reporting, all dimensions matter. For example, an asset balance must be accurate (matches the general ledger), complete (every balance is reported), valid (currency format, non-negative), and timely (as of the report date). Consistency ensures that if two reports reference the same exposure, they use the same amount. Defining these dimensions allows setting measurable targets: e.g. 99% of accounts must be filled (completeness threshold), or 100% of country codes must match ISO lists (validity).

Banks implement data quality frameworks that automate checks against these dimensions. Scorecards might flag any loans with null values (completeness) or duplicate customer IDs (uniqueness). Working these dimensions into BCBS 239 compliance means building controls for each: reconciliation for accuracy, data completeness reports, etc.

```text
Data Quality Dimensions
+-----------+-----------+-----------+
| Accuracy  | Timeliness| Consistency|
| Completeness| Validity| Uniqueness|
+-----------+-----------+-----------+
```

### Permanent rule

All regulatory data must meet the necessary quality dimensions for its use. Missing or outdated key data invalidates a report.

### Permanent trap

Focusing on only one dimension (e.g. only completeness) while ignoring others (like not verifying that “complete” data is accurate).

### Never confuse

**Accuracy** — Data matches the true value or source system.

---

**Consistency** — Data is uniform across systems (e.g. same value for Customer ID in trading vs risk systems).

### Jurisdiction variants

**No delta.** Data quality dimensions are agreed best practice in all jurisdictions; regulators expect rigorous checks regardless of country.
