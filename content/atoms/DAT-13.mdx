### Core mechanism

| Dimension | Master data | Reference data |
| :--- | :--- | :--- |
| Represents | Core business entity | Permitted classification or code set |
| Example | Counterparty record, product record, legal entity | Currency code, country code, sector code, rating scale |
| Typical key problem | Duplicate or mismatched identity | Invalid, stale or inconsistent classification |
| Change pattern | Entity created, merged, amended or retired | Code added, mapped, versioned or withdrawn |
| Risk impact | Exposure split across duplicate identities | Exposure grouped into wrong category |

```text
Transaction
    ↓
Link to master entity
    ↓
Apply governed reference classifications
    ↓
Aggregate by customer, legal entity, product, sector, country or currency
```

The two interact. A counterparty master record may carry a country code from a controlled reference set; an exposure can be correctly linked to the customer yet still be misreported by geography if the reference code is wrong.

### Where it sits

```text
Upstream:   Metadata · Business entities · External and internal classifications
This:       Master and reference data governance
Downstream: Aggregation keys · DQ validation · Mapping · Regulatory classifications
```

### Never confuse [Master data] and [Reference data]

**Master data** - governed records for the core entities with which the bank does business or about which it reports.

---

**Reference data** - governed lists and codes used to classify, validate or interpret other data.

### Permanent rule

Shared identifiers and classifications must be governed consistently across the reporting chain; local copies require controlled synchronisation or reconciliation.

### Permanent trap

Fixing an aggregation problem only in the report. If the root cause is duplicate customer master data or a stale classification code, a report-level override leaves other consumers wrong.

### Jurisdiction variants

**No delta.** Jurisdictions can prescribe different classifications or reporting codes, but the distinction between master and reference data does not change.

  a="Duplicate or mismatched entity identities can split one economic counterparty across records, understating the aggregated concentration even when transaction amounts are correct."
