### Core mechanism

To select the latest snapshot for each account:

```sql
WITH ranked AS (
    SELECT
        account_id,
        reporting_date,
        outstanding_balance,
        ROW_NUMBER() OVER (
            PARTITION BY account_id
            ORDER BY reporting_date DESC
        ) AS rn
    FROM loan_snapshots
)
SELECT account_id, reporting_date, outstanding_balance
FROM ranked
WHERE rn = 1;
```

For the first payment, reverse the order:

```sql
WITH ranked AS (
    SELECT
        account_id,
        payment_date,
        payment_amount,
        ROW_NUMBER() OVER (
            PARTITION BY account_id
            ORDER BY payment_date, payment_id
        ) AS rn
    FROM payments
)
SELECT account_id, payment_date, payment_amount
FROM ranked
WHERE rn = 1;
```

The second ordering column matters when multiple payments can share a date. Without a stable tie-breaker, two equally eligible rows can swap between executions.

`ROW_NUMBER` can also resolve a known hierarchy such as "prefer active source record, then latest update." It should not be used to conceal unexplained duplicates. If two source rows are supposed to be identical at the business key, investigate why both exist rather than arbitrarily assigning one `rn = 1`.

`RANK` and `DENSE_RANK` are different tools: tied values receive the same rank, so filtering `rank = 1` may return multiple rows. Use them only when ties are intentionally retained.

### Never confuse [ROW_NUMBER] and [RANK]

**ROW_NUMBER** - assigns a unique sequence number even when ordered values tie.

---

**RANK** - gives tied rows the same rank and may return several rows at rank one.

### Permanent rule

Every one-row selection must have a business-valid ordering and a deterministic tie-breaker where ties are possible.

### Permanent trap

Using `ROW_NUMBER` to make a broken key unique. Ranking can choose a survivor while hiding the fact that the source contains competing records at a supposedly unique grain.

### Jurisdiction variants

No delta. Ranking mechanics do not vary by regulator.
