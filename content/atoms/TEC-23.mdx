### Core mechanism

Suppose `portfolio` contains one August row per account plus `product_type` and `customer_id`. Summarize by product with named aggregations:

```python
summary = (
    portfolio.groupby("product_type", as_index=False)
    .agg(
        accounts=("account_id", "nunique"),
        customers=("customer_id", "nunique"),
        outstanding_balance=("outstanding_balance", "sum"),
        average_dpd=("days_past_due", "mean"),
    )
)
```

Each output measure states its input column and aggregation. `nunique` is often preferable to row count when the business question asks for unique entities, but it is not a universal substitute: if the input grain is already one row per account, row count and account count should agree and that agreement itself can be checked.

For multiple grouping dimensions, include all dimensions that define the desired result grain:

```python
vintage_summary = (
    portfolio.groupby(["product_type", "vintage_month"], as_index=False)
    .agg(
        accounts=("account_id", "nunique"),
        balance=("outstanding_balance", "sum"),
    )
)
```

Missing group keys are a deliberate choice. Depending on pandas version and parameters, missing keys may be dropped unless `dropna=False` is requested. If UNKNOWN segment is analytically meaningful, decide how it should appear rather than letting a default silently remove those rows.

After aggregation, validate that balance totals tie to the input where the grouping is intended to partition rather than filter the portfolio.

### Never confuse [Row count] and [Entity count]

**Row count** - number of DataFrame records at the current grain.

---

**Entity count** - number of unique accounts, facilities, or customers answering the business question.

### Permanent rule

Write every grouped output so its grouping grain and counting unit are obvious from the code.

### Permanent trap

Using `.count()` as a general row count. It counts non-missing values in the selected column and can understate groups when that column contains missing data.

<Recall
  q="Why use named aggregations in a credit portfolio summary?"
  a="They make each output field's source column and aggregation explicit, reducing ambiguity when several measures are produced together."
/>

<Recall
  q="What does `nunique` answer that a row count may not?"
  a="It counts distinct entities such as accounts or customers even when the DataFrame contains repeated rows for those entities."
/>

<Recall
  q="What should be checked after a grouping that partitions the whole portfolio?"
  a="Controlled measures such as total outstanding balance should tie back to the input unless the grouping intentionally excludes records."
