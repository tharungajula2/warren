### Core mechanism

Reconstruct the present state before designing the future state, using evidence from both policy and operation.

```text
Documents -&gt; SME walkthrough -&gt; User observation -&gt; Exceptions and controls -&gt; Reconciled as-is
```

| Examine | What to establish |
| :--- | :--- |
| Trigger and inputs | What starts work and what must already exist |
| Activities | What actually happens, in sequence |
| Decisions | Who chooses, under which rule |
| Handoffs | Where ownership moves |
| Controls | What prevents or detects error |
| Exceptions | What happens when normal flow fails |
| Manual work | Spreadsheets, email or adjustments keeping the process alive |
| Calendar | Day-end, month-end and reporting-cutoff differences |
| Policy versus practice | Authorised process and reason for live deviation |
| Evidence base | Documents, walkthroughs, observation and records |

Seniority does not settle factual contradictions. Reconcile owner and operator accounts into an approved process, accepted workaround or explicit change problem; this also protects hidden controls and peak-period dependencies from being designed away.

### Where it sits

```text
Upstream:   Problem framing · Stakeholders · Existing process evidence
This:       As-is process · Controls · Exceptions · Handoffs
Downstream: Scope · Requirements · Impact analysis · Operational readiness
```

### Ownership

| Role | Responsibility |
| :--- | :--- |
| Produces | BA reconstructs and validates the as-is view |
| Approves | Process owner confirms the governed baseline and known deviations |
| Consumes | Requirements, design, testing and operations teams use the baseline |
| Independently challenges | Control functions challenge omitted controls or unrecognised workarounds where relevant |

### Permanent rule

A future-state design is unsafe until the current controls and exceptions are understood. Removing a manual step can remove a manual control at the same time.

### Never confuse [Documented process] and [Operating process]

**Documented process** - the approved or described way work is intended to happen.

---

**Operating process** - the way work is actually completed, including exceptions and workarounds.

### Permanent trap

Treating undocumented work as irrelevant because it "should not happen". If the bank depends on it today, migration must either preserve the outcome or deliberately eliminate the dependency.

No delta.

  a="They expose hidden dependencies and controls that happy-path documentation misses."

<Recall
