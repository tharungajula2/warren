### Core mechanism

```text
Start with baseline prediction
    ↓
Measure current loss gradient for every borrower
    ↓
Fit a small tree to the needed correction
    ↓
Scale correction by learning rate
    ↓
Add tree to ensemble
    ↓
Repeat until stopping rule
```

| Control | Lower setting tends to | Higher setting tends to |
| :--- | :--- | :--- |
| Learning rate | Require more trees, smaller steps | Fit faster, greater overfit risk |
| Tree depth | Capture simpler local structure | Capture stronger interactions and noise |
| Number of trees | Underfit if too few | Overfit if too many without control |
| Row/feature subsampling | Add randomness and regularisation | Use more information per tree but less randomness |

For binary default classification, boosting commonly optimizes a logistic-type loss, so the additive ensemble often operates on a score or log-odds scale before mapping to probability.

### Where it sits

```text
Upstream:   Trees · Logistic loss · Nonlinear interactions
This:       Sequential correction · Learning rate · Additive ensemble
Downstream: Attribution · Generalisation · Calibration
```

### Formula

```text
Model after step t = model after step t-1 + learning rate x new tree output
```

### Permanent rule

Boosting performance is the product of many small modelling choices; iteration count cannot be interpreted without learning rate and tree complexity.

### Never confuse [Gradient boosting] and [Random forest]

**Gradient boosting** - sequentially adds trees to reduce current loss.

---

**Random forest** - averages many decorrelated trees whose main role is variance reduction.

### Permanent trap

Selecting the number of boosting rounds on the same data later used to claim final performance. That turns the evaluation sample into part of model tuning.

### Jurisdiction variants

No delta. Gradient-boosting mathematics is universal.

<Recall
  q="Why does a lower learning rate usually require more trees?"
  a="Each tree contributes a smaller correction, so more sequential steps are needed to reach a comparable fitted function."
/>

<Recall
  q="What role does a shallow tree play in boosting?"
  a="It acts as a weak local correction that captures a limited pattern; many such corrections combine into a flexible nonlinear model."
/>

<Recall
  q="Why can boosting overfit despite using small trees?"
  a="Sequentially adding enough corrections can eventually fit noise, especially when stopping decisions are tuned repeatedly on the same validation data."
/>
