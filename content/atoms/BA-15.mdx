### Core mechanism

Use a dependency lens, not only a system list.

| Dimension | Questions |
| :--- | :--- |
| Process | Which activities, handoffs, cutoffs or exceptions change? |
| People | Which roles perform, approve, support or rely on the process? |
| Controls | Which preventive, detective or approval controls move or disappear? |
| Systems | Which applications send, receive, calculate or store affected information? |
| Data | Which sources, definitions, transformations or outputs are affected? |
| Reports | Which management, finance or regulatory outputs consume the change? |
| Models | Does the change alter a model input, output, use or operating process? |
| Access | Which entitlements or segregation-of-duties patterns change? |
| Calendar | Does cutover touch day-end, month-end, quarter-end or filing windows? |
| Operations | Which incident, reconciliation or support process must change? |

One-line specialist reminders are enough: model governance remains with MRM; statistical method with QNT; SQL/Python implementation with TEC; Indian regulatory substance with IND; data sourcing and mappings with DAT.

Dependencies have direction. If system A feeds B, a format change in A affects B even when B is out of build scope. Record owner, dependency, impact and required action.

```text
Changed requirement -&gt; Changed capability -&gt; Upstream dependencies + Downstream consumers -&gt; Required actions
```

### Where it sits

```text
Upstream:   Scope · Requirements · As-is process · Traceability
This:       Blast radius · Dependencies · Required actions
Downstream: Design challenge · Change control · Test governance · Readiness
```

### Ownership

| Role | Responsibility |
| :--- | :--- |
| Produces | BA coordinates cross-domain impact analysis and dependency record |
| Approves | Affected owners confirm impacts within their domains |
| Consumes | Planning, design, testing, operations and governance use identified dependencies |
| Independently challenges | Risk and control functions challenge omitted control or risk impacts |

### Permanent rule

Out of build scope does not mean out of impact scope. Anything the change can disrupt needs an owner and an assessed consequence.

### Never confuse [Scope] and [Impact]

**Scope** - what the programme commits to change or deliver.

---

**Impact** - everything whose behaviour, control, timing or outcome may be affected by that change.

### Permanent trap

Asking only "which systems change?" A system-centric impact assessment misses operating procedures, controls, access, reporting calendars and manual reconciliations that can be equally critical to production safety.

### Jurisdiction variants

No delta.
