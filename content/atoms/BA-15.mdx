The testing process is layered:
- **Unit Testing:** done by developers on individual code modules. Ensures each component works as intended.
- **Integration Testing:** QA or IT tests combined modules or subsystems. Checks interfaces between components.
- **System Testing:** QA tests the complete system against requirements (functional and non-functional).
- **User Acceptance Testing (UAT):** Business users test end-to-end business scenarios in a production-like environment. UAT is led by the business (operations, product, compliance teams).  UAT ensures the system meets real business needs before go-live.

Each test type requires different participants: developers own unit tests, QA owns system/integration tests, and business stakeholders perform UAT.  Testing each phase is critical: skipping system test and jumping to UAT, for instance, risks missing defects that developers should have caught.

### Permanent rule

Follow all test phases in order and involve the right people. Use unit and system tests to catch defects early, and let end users validate the solution in UAT.

### Permanent trap

Treating UAT as the first time the business sees the solution. If unit/integration tests are inadequate, UAT will be overwhelmed with obvious issues.

### Never confuse

**System Test** vs **User Acceptance Test (UAT)**:
*System Test* is executed by QA/IT to verify the software meets the specified requirements. *UAT* is done by business users to verify the system meets their needs in real-world scenarios.

### No delta

These test phases and roles are standard in all banking projects globally.
