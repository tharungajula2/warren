  In SQL, `NULL` represents missing or unknown data. Comparisons with `NULL`
  yield *UNKNOWN*, not true or false. SQL employs three-valued logic (TRUE,
  FALSE, UNKNOWN). For example, `NULL = NULL` is UNKNOWN, so a `WHERE` filter
  excludes those rows. To test for missing data use `IS NULL` or `IS NOT NULL`.

For instance, to find accounts without an open date:
```sql
SELECT AccountID FROM Accounts WHERE OpenDate IS NULL;
```
Regular operators (`=`, `&lt;`, etc.) cannot be used with NULL. Use `ISNULL()` or `COALESCE()` functions to substitute defaults when needed.

### Permanent rule

Always use `IS NULL` or `IS NOT NULL` to check for NULL values.

### Permanent trap

Treating NULL as a value in conditions (e.g. `WHERE Balance != 0` won’t catch NULL balances). Also, when using `JOIN`, NULLs can cause unmatched rows.

### Never confuse

**NULL** — absence/unknown value (three-valued logic).
---
**0** — numeric zero, a definite number (not NULL).

### Jurisdiction variants

**No delta.** SQL’s handling of NULLs is universal.
