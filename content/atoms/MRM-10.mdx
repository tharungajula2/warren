### Core mechanism

| Development mandate | Question |
| :--- | :--- |
| Objective | What problem is the model solving? |
| Output | What exactly will it estimate, rank, classify or optimise? |
| Population | For which customers, products, markets or processes? |
| Horizon | Over what time period is the output meaningful? |
| Intended use | Which decisions may consume the output? |
| Prohibited use | Where must it not be used without further analysis? |
| Performance criteria | What evidence will count as adequate? |
| Limitations | Which assumptions, data gaps or boundary conditions remain? |
| Alternatives | What happens if the model is unavailable or unsuitable? |

Purpose → data choice → methodology → testing → validation → use conditions

A one-line reminder is enough where the model produces familiar risk parameters: PD, LGD and EAD are model outputs used in credit-risk contexts; their substantive estimation belongs elsewhere. MRM asks whether the model's stated purpose and permitted use match the evidence.

### Where it sits

```text
Upstream:   Business need · Model tier · User requirements
This:       Purpose, intended use and limitations
Downstream: Data design · Method selection · Testing · Validation criteria
```

### Ownership

| Role | Responsibility |
| :--- | :--- |
| Business user | Defines decision context and operational need |
| Model owner | Owns documented purpose and use boundaries |
| Developer | Designs consistently with that mandate |
| Validation | Challenges whether mandate and evidence align |

### Permanent rule

A model is fit for a use, not "fit" in the abstract. Change the use materially and the original evidence may no longer support the decision.

### Never confuse [Limitation] and [Defect]

**Limitation** - known boundary or uncertainty inherent in the model that may be acceptable with controls.

---

**Defect** - error or failure that makes the model inconsistent with its approved design or required standard.

### Permanent trap

Writing broad purposes such as "risk management". Vague mandates make almost any data, method or later use appear defensible and prevent meaningful challenge.

### Jurisdiction variants

No delta. Clear purpose, intended use and understanding of limitations are universal development and use principles; regulators differ mainly in scope and prescription, not in this mechanism.

<Recall
  q="Why must prohibited uses be documented as well as intended uses?"
  a="They convert known model boundaries into operational controls, preventing users from treating a validated model as reliable for every superficially similar decision."
/>

<Recall
  q="Why does changing model use create model risk even if code is unchanged?"
  a="Reliability evidence is conditional on the original population, horizon and decision context. A new use can introduce uncertainty the original testing never addressed."
